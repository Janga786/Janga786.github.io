# Jangara Bliss — Robotics Portfolio

An evidence-first graduate-admissions portfolio for Jangara Bliss, a computer engineering student focused on robot learning and autonomy. The site is intentionally explicit about what was completed in simulation, what ran on hardware, what remains active research, what came from a team or course, and which upstream systems made the work possible.

The public narrative centers on five proof points:

- Booster K1 / NaVILA navigation research — complete 1,077-episode simulation benchmark and active viewpoint study
- xembench — executed cross-embodiment manipulation benchmark and intervention campaign
- KUKA KR 6 kinematics — mathematical implementation and independent verification
- CLiDA / LiDAR motion analysis — attributed five-person sensing project with controlled final trials
- NASA Colorado Robotics Challenge hexapod — fielded team system plus a later CPG study

Supporting case studies cover legacy robot restoration, embedded/FPGA/PCB breadth, and the KDUR data platform.

## Tech stack

- Next.js 16 App Router with static export (`output: "export"`)
- TypeScript and Tailwind CSS v4
- Framer Motion for restrained reveals
- GitHub Pages deployment from `out/`

## Content architecture

All public copy lives under `content/`:

- `profile.ts` — bio, research direction, education, capabilities, leadership, and graduate-study goals
- `projects.ts` — case studies, metrics, contribution boundaries, provenance, evidence, limitations, and links
- `writing.ts` — canonical reports and evidence ledgers; no planned-content cards
- `timeline.ts` — concise technical trajectory
- `site-config.ts` — canonical URL and visibility toggles

Project pages use four distinct status labels: active research, completed study, fielded system, and validated library. The separate `provenance` field records team ownership, course context, upstream frameworks, inherited code, AI-assisted implementation, and simulation/hardware boundaries.

## Media and evidence

- `public/diagrams/` contains deterministic SVG system diagrams.
- `public/media/` contains project photographs, videos, and report-derived figures.
- `public/og/robotics-evidence-social.png` is the generated social-card background used by `app/opengraph-image.tsx`.
- `public/resume.pdf` is generated by `scripts/generate_resume.py`.

External artifacts link to the canonical GitHub repository, result report, evidence ledger, or methods documentation. Files without a defensible public source are not presented as evidence.

## Deployment

The repository targets GitHub Pages. Pushing to `main` triggers `.github/workflows/deploy.yml`, which runs `npm ci && npm run build` and publishes `out/`.

If the production domain changes, update `siteUrl` in `content/site-config.ts`.

## Evidence policy

- Do not convert a hardware clip into a model-control claim without synchronized command or model traces.
- Do not publish a detector metric without a preserved held-out split and result artifact.
- Distinguish designed, fabricated, assembled, and validated hardware milestones.
- Name team roles, course origins, upstream frameworks, inherited code, and AI-assisted implementation.
- Preserve denominators, per-episode artifacts, and negative results.
- Keep limitations visible; an unsupported number is removed, not softened.
